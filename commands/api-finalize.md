# /api-finalize — commit + push + PR

Separate from `/api` on purpose (decision C in `docs/v1.0-plan.md`): this is the inspection point. The user has had a chance to review the gatekeeper-approved diff before anything leaves the local machine.

Decisions verrouillées:
- Stage explicitly per-file (never `git add -A` / `git add .`).
- Never `--amend`, never `--no-verify`, never `--no-gpg-sign`.
- Skip secret-like paths even if `git status` lists them.
- Skip legacy `.claude/last-api-*.md` state files (v0.1 leftovers).

---

## 1. Pre-flight assertions

!git rev-parse --show-toplevel
!git symbolic-ref --short HEAD 2>/dev/null || echo "DETACHED_HEAD"
!git status --porcelain
!git diff --cached --stat

Hard checks:
- Must be inside a git repo.
- Must NOT be on `main` / `master` / `develop`. If so: STOP and tell the user to switch to a feature branch first.
- `git status --porcelain` must be non-empty (there is something to commit). If empty: STOP — nothing to finalize.
- If a rebase / merge / cherry-pick is in progress (`.git/MERGE_HEAD`, `.git/REBASE_HEAD`, etc.): STOP, ask the user to resolve first.

---

## 2. Parse flags

User input: `$ARGUMENTS`

- `--no-push` → set `PUSH=false` (default `true`)
- `--no-pr` → set `OPEN_PR=false` (default `true`)

---

## 3. Build the staging list

Read the full output of `git status --porcelain`. For each entry, **include or exclude** with these rules:

**EXCLUDE** (do not stage):
- Any path matching the pre-tool-use secret patterns: `.env*`, `*.pem`, `*.key`, `*.p12`, `*.pfx`, `*credentials*`, `*.crt`, `id_rsa`, `id_ed25519`, `id_ecdsa`, `*.kdbx`.
- Legacy state files: `.claude/last-api-*.md`, `.claude/api-*.tmp`, `.claude/last-api-*`.
- Memory snapshots created mid-flow: anything under `.claude/memory-snapshots/` unless the user explicitly asked to include them.
- Any path the user has gitignored (already filtered out by `git status`, but double-check).

**INCLUDE** (stage):
- Everything else in the porcelain output.

If anything was excluded: print the excluded list with the reason. Ask the user to confirm before continuing.

Stage with explicit paths: `git add -- <path1> <path2> ...`. Never use `-A` / `.`.

---

## 4. Compose the commit message

Use the gatekeeper-approved plan + implementer report from the conversation context. The message must be:

```
<scope>: <subject — imperative, ≤ 72 chars>

Why:
  <1-3 sentence rationale tied to the original /api story>

What:
  - <bullet of the main change>
  - <bullet>
  - <bullet>

Verification:
  - gerard-gatekeeper APPROVE
  - tests: <list of test commands run, all passing>
  - AppSec bilan: <status — no H1/H2 open>
```

Pick `<scope>` from the touched paths: `api`, `doctrine`, `security`, `tests`, etc. If multiple, use the broadest applicable (`api` covers most stories).

Do NOT add a "Generated by Claude" trailer. Do NOT amend an existing commit.

---

## 5. Commit

```bash
git commit -m "$(cat <<'EOF'
<message body from step 4>
EOF
)"
```

If the commit fails (hook rejection, signing issue): investigate. Never use `--no-verify` / `--no-gpg-sign` as a shortcut. Fix the root cause, re-stage if needed, create a NEW commit (never `--amend` to recover from a hook failure).

---

## 6. Push (skip if `--no-push`)

!git rev-parse --abbrev-ref --symbolic-full-name @{u} 2>/dev/null || echo "NO_UPSTREAM"

- If there is no upstream: `git push -u origin <current-branch>`.
- If there is an upstream: `git push`.
- Never `--force` / `--force-with-lease` from this command. If a non-fast-forward push is needed, STOP and ask the user.

---

## 7. Open a PR (skip if `--no-pr`)

Require `gh` to be installed. If absent: print a message and skip — the user can open the PR manually.

!command -v gh >/dev/null 2>&1 && echo "gh_present" || echo "gh_missing"

When `gh` is present:

```bash
gh pr create --title "<subject from commit>" --body "$(cat <<'EOF'
## Summary
<2-3 bullets from the commit Why + What>

## How it was built
- Architect-trio plan: <one-line summary>
- Implementer: <one-line summary>
- Gatekeeper: APPROVE

## Test plan
- [ ] <test command 1>
- [ ] <test command 2>

## AppSec
<copy the gatekeeper's AppSec bilan table verbatim>

## Out of scope
<copy the gatekeeper's Out-of-scope section verbatim>
EOF
)"
```

Print the resulting PR URL.

---

## 8. Final report

One-line success:
> `gerard: <branch> committed (<sha>) + pushed + PR opened (<url>).`

Or, if `--no-push` / `--no-pr` were set, report what was skipped.
